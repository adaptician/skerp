Make sure a UI item is built from the design that actually exists, is approved, and has not moved. Designs
that existed have repeatedly gone unfound because the lookup fired on the word "Figma" rather than on the
work. This skill fires on the **work**.

> **Read-only against Figma.** This skill never writes to a Figma file. The only thing it may write is an
> `approved` field in the screen index, for a frame a human names as approved in the session.

## 1. Decide applicability — and record it either way

It **applies** when any of these is true:

- the item has a UI surface — a screen, component, email, or any change a user can see — whatever its type;
- a Design item is linked to it, or a Figma link is on the item or any ancestor (Feature, Epic, Deliverable);
- its plan already cites screen-index keys or Figma nodes.

Otherwise it is **not applicable**. A Spike or Refactor with no UI surface is the usual case.

Write exactly one line where the caller asks (the plan for `locate`; the run-log entry or review findings
for `verify`):

```
design-fidelity-check: applies — <reason>
design-fidelity-check: not applicable — <reason>
```

**A skip is never silent.** If not applicable, record the line and return; the caller carries on.

## 2. Load the design standards

When it applies, read these **in full** before anything else — this skill is how they reach the decision
point (they are Tier 2 and not loaded by path triggers):

- [`technologies/figma.md`](../../standards/technologies/figma.md) — lookup, *No design, no build*, approval, screen index, naming, retrieval
- [`solution/figma.md`](../../standards/solution/figma.md) — which file governs which app; the index format
- [`design.md`](../../standards/design.md) and [`styling.md`](../../standards/styling.md) — tokens, theming, reuse

Where this skill and those standards differ, **the standards win**; raise the difference.

## 3. Check access, then apply the stop rules

The rules are `technologies/figma.md` → *No design, no build*, applied in this order. Do not reword them into
something softer.

1. **No Figma access** (connector missing, disconnected, unauthenticated) → ask for the connection to be
   restored, for exported frames, or for explicit approval to proceed without designs. Neither given →
   **stop and ask for designs.** Never proceed from a text description, ADO text included. Exported frames or
   an approval to proceed are recorded in the plan (who, when, what).
2. **Access, but the design is missing** — a cited node does not exist live, or the governing file has no
   design for the feature → **stop and raise the gap.** Do not substitute a similar screen, another file, or
   prose. Absence from the index alone is not a missing design.
3. **A stock framework screen** that the solution has explicitly accepted as stock (recorded in
   [`solution/figma.md`](../../standards/solution/figma.md) or the plan) is not a missing design. Where no such
   decision is recorded, **ask a human per screen** and record the answer in the plan.
4. **A frame that is not approved** (below) → **stop and raise it.** Never build from a draft.

## 4. Retrieval — how to read the file

- Load the Figma plugin's **`figma-use`** skill before any `use_figma` call.
- **Enumerate pages with `use_figma`** (`figma.root.children`). Never treat `get_metadata`'s page listing
  (called without a `nodeId`) as complete — it has been observed to list 2 of a file's 5 pages.
- Ignore the `🗄️ Archive` page. A cited frame found there is drift.
- Query a frame placed in its theme's mode on that theme's page, not a bare master on a shared master page (`Components / Icons`, `Buttons`, `Form Inputs`, `Cards`, `Badges`, `Navigation` or `Shared`; see `technologies/figma.md` → *Naming convention*).
- Use the file [`solution/figma.md`](../../standards/solution/figma.md) names for the app — never another.

## 5. `locate` — planning

Run from `plan-work-item` (and from `run-milestone` if the plan does not already cite frames).

1. List every screen and state the item touches, at each breakpoint it ships.
2. Resolve each one:
   - **Indexed** — find its key in [`figma-screen-index.json`](../../standards/solution/figma-screen-index.json)
     and confirm live that the node exists and its name still slugs to the key. Cite it as
     `` `client/profile/view/desktop` (`123:456`) ``.
   - **Not yet indexed** (a frame added since the index was built; any file the index does not
     list) — find it live by enumerating pages, and cite it by full URL with `node-id`. Do not add an index
     entry for a frame whose name does not follow the naming convention.
3. **Approval.**
   - Indexed frame with `approved` recorded → approved.
   - Otherwise ask a human whether the frame is marked Ready for dev. If they confirm, record who, when and
     which frame in the plan, with the frame's **fingerprint** (§7). For an **indexed** frame also write its
     `approved` field (`by`, `on`, `fingerprint`) — in **its own commit**, so a code owner reviews the
     approval in the PR (the index is code-owned; that review is intended).
   - Not confirmed → stop (§3.4).
4. **Write the citation table into the plan** (the spec, or the ADO Description below 5 points):

   | Screen · state · breakpoint | Citation | Page | Approval | Fingerprint |
   |---|---|---|---|---|
   | Client profile · view · desktop | `` `client/profile/view/desktop` (`123:456`) `` | 👤 Screens / Client | index: <human>, 2026-10-02 | `fp1:…` |

   plus any exported frames, approvals to proceed without designs, and stock-screen confirmations.

## 6. `verify` — after implementation

Run from `run-milestone` at milestone close, and from `conformance-review` and `coherence-review`. When
`locate` ran earlier in the same session, this is the **second pass**: it checks that what was built aligns
with what was located.

For **each frame the plan cites**, live:

| Check | Drift when |
|---|---|
| Exists | the node is gone |
| Name | an indexed frame's live name no longer slugs to its key (slug rule: `technologies/figma.md`) |
| Page | the frame is on Archive; or not on its theme's page (`🛡️ Screens / <Theme>` per `technologies/figma.md` → *Naming convention*); for a file not yet migrated to that convention, not on the page recorded at `locate` |
| Theme mode | for a themed frame, once the file is migrated: the frame does not resolve its theme's mode (`node.resolvedVariableModes` via `use_figma`; name each collection and mode with `figma.variables.getVariableCollectionByIdAsync`, since library collections are not local) — its values would be another theme's. Before migration a file may have only a scheme collection (`Light`/`Dark`): record the resolved modes at `locate` and report any change |
| Approval | an indexed frame's `approved` is now missing |
| Fingerprint | the fingerprint differs from the one recorded at approval — the frame was **edited after approval** |

**Any drift stops the hand-off.** Report it and ask a human; do not "fix" either side on your own. A frame
edited after approval needs a human to re-approve (a new fingerprint) or the build to follow the new design.

### The verification bar

Then run **the verification bar** ([`design.md`](../../standards/design.md) → *Verifying an Implementation
Against Its Design*) on the built surface. Run it for each cited frame, at each breakpoint the item ships,
for each theme, and once more with the browser's colour scheme set to light (`resize_window` with
`colorScheme: light`). The standard defines the levels. This is how to run them:

| Level | How | Fails when |
|---|---|---|
| 1 Tokens | `get_variable_defs` on the frame, placed in its theme's mode; compare with the page's computed styles (`javascript_tool`, `getComputedStyle`) and the tokens in `styling.md` | a raw literal where a variable is bound; a token from another theme |
| 2 Inventory | list the frame's elements per region (`get_metadata`); list the page's elements in the same region (`read_page`); compare in both directions | a difference that is not fixed and has no human approval recorded before implementation (pre-flight or plan) |
| 3 Visual | `get_screenshot` of the frame; browser screenshot with the viewport resized to the frame's width; judge them side by side | typography, colour, borders, spacing, position or layout differ. Pixel noise alone does not fail |
| 4 Mechanism | for each behaviour the design depends on, instrument it and observe it: a listener fired, `defaultPrevented`, the request appeared in `read_network_requests` | the end state is right but nothing shows the mechanism ran |

Record what was compared for each judgement, so a reviewer can repeat it. A level that does not apply
(level 4 on a static screen) is recorded as `n/a` with its reason, never left blank.

**No screenshot, no pass.** If the browser screenshot or Figma `get_screenshot` does not work, mark level 3
`unverified`, never `pass`. Record which tool failed. Then add a human visual sign-off step to the item's
How To Test, or the equivalent field, through the plan or spec it is generated from. List the frames,
breakpoints, themes and the light-scheme check for the human to compare.

Report one row per screen, breakpoint and theme, plus the light-scheme row:

| Screen · breakpoint · theme | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| `client/profile/view/desktop` · client | pass | pass | pass | n/a — static |
| `client/profile/view/desktop` · light device | pass | pass | pass | n/a — static |

**Any `fail` or `unverified` stops the hand-off**, the same way drift does.

Record the result where the caller asks:

```
design-fidelity-check verify: pass — <n> frames, levels 1–4 (<breakpoints> × <themes> + light device)
design-fidelity-check verify: DRIFT — <frame citation>: <check> — <what differs>
design-fidelity-check verify: FAIL — <frame citation> · <breakpoint> · <theme>: L<n> — <what differs>
design-fidelity-check verify: UNVERIFIED — <frame citation>: L3 — <tool> unavailable; sign-off step added to How To Test
```

## 7. The fingerprint

[`fingerprint.js`](fingerprint.js) computes a structural fingerprint (`fp1:<16 hex>`) per frame. **Pass the
file's text verbatim** as the code of a read-only `use_figma` call, editing only the `NODE_IDS` line.
Paraphrasing it changes the algorithm and makes every stored fingerprint look like drift. Its stability
across reads was measured (identical output from separate reads of unchanged frames); re-measure it, and
record the result in the assumption ledger, before relying on it in a solution whose Figma plugin sandbox
may differ.
It covers structure, sizes, positions, fills, strokes, effects, text and instance sources; it does not cover
every visual property, so it complements the visual comparison rather than replacing it.

## What this skill does not do

- Write to Figma, or approve a frame on a human's behalf.
- Decide a design question. Missing, unapproved or drifted → stop and raise it.
- Replace the offline gate check (`check-screen-index.mjs` in `verify.mjs`), which validates the index and
  spec citations without Figma access. This skill does the live half.
